# Reference Standards

References are part of the curriculum, not an unreviewed bookmark collection.
Every link should have a learning purpose and enough metadata to decide whether
it is current and relevant.

## Source priority

1. Standards and specifications
2. Official product documentation and architecture guidance
3. First-party engineering publications and conference sessions
4. Recognized foundations such as CNCF, NIST, OWASP, and FinOps Foundation
5. Books with durable architectural value
6. Carefully reviewed community content

## Required metadata

Each module reference list records:

- title and URL;
- source organization or author;
- type: documentation, standard, video, book, paper, lab, or talk;
- level: foundation, advanced, or architect;
- why it is recommended;
- publication/version information when relevant;
- last-verified date.

## Curation rules

- Link to the canonical source rather than a search result or content mirror.
- Prefer a small, high-signal reading path over dozens of unexplained links.
- Do not copy documentation or video transcripts; summarize in original words.
- Mark vendor claims as vendor guidance rather than universal fact.
- Flag version-sensitive pages and revisit them at least quarterly.
- Replace deleted or obsolete resources; preserve the reason in Git history.
- Reject interview dumps, leaked questions, and unexplained certification lists.
