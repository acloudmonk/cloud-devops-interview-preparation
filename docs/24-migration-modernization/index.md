# Cloud Migration & Modernization

[← Curriculum overview](../curriculum/index.md) · [Master competency map](../master-competency-map.md)

Last reviewed: **2026-10-11**
Level: **Senior / Architect**

Migration is a business and operating-model change enabled by technology. A strong
plan connects outcomes, portfolio evidence, dependencies, target-platform readiness,
waves, data integrity, cutover, rollback, operational acceptance, modernization, and
measured value. It does not treat a migration-strategy label as the whole plan.

!!! tip "Where to start"
    Start with **1. Migration and modernization decision model** and follow the
    numbered path. AWS is the primary implementation context, with Azure, Google
    Cloud, VMware, and portable-pattern translations. This is a documentation and
    interview-practice module; no deployment lab is required.

## Learning objectives

- connect business outcomes, constraints, and success measures to migration scope;
- build a trustworthy portfolio inventory and dependency model;
- choose among rehost, replatform, refactor, repurchase, relocate, retire, and retain;
- prove landing-zone, security, network, operations, capacity, and support readiness;
- form dependency-aware waves and operate a repeatable migration factory;
- design data movement, coexistence, cutover, rollback, and reconciliation;
- define functional, performance, security, resilience, and operational acceptance;
- modernize selectively using evidence instead of ideology;
- govern risk, cost, benefits, skills, vendors, decommissioning, and value realization;
- translate AWS-first decisions to Azure, Google Cloud, and hybrid environments.

## Scope boundary

[Cloud Architecture](../01-cloud-architecture/index.md) covers general target-system
design, [Database Architecture](../23-databases/index.md) covers engine-level data
migration, and [HA/DR](../25-ha-dr-bcp/index.md) covers enterprise continuity. This
module owns portfolio decisions, readiness, migration waves, transition control,
operational acceptance, modernization sequencing, decommissioning, and benefits.

## Completion checklist

- [ ] I can turn a business deadline into measurable migration outcomes and constraints.
- [ ] I can challenge incomplete inventory and dependency data without blocking discovery.
- [ ] I can defend a workload-level disposition and target state.
- [ ] I can define landing-zone and wave entry/exit gates.
- [ ] I can explain data synchronization, fencing, cutover, rollback, and reconciliation.
- [ ] I can distinguish technical completion from operational and financial completion.
- [ ] I can prioritize modernization using value, risk, effort, and evidence.
- [ ] I answered every scenario aloud and completed the scored mock interview.
