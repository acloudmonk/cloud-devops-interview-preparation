# Git Active-Recall Flashcards

[← Module overview](index.md) · [Master competency map](../master-competency-map.md)

Use each prompt without viewing the cue. Explain object/graph behavior,
collaboration impact, and the safe next question.

| Prompt | Answer cue |
| --- | --- |
| Object graph | blobs → trees → commits with parent links; refs name objects |
| Branch deletion | removes a name; reachable objects may remain through other refs/reflogs |
| Detached HEAD | direct commit checkout; create a branch to retain new work |
| Index role | next-tree proposal and multi-stage conflict state |
| Fetch versus pull | update observations versus fetch plus configured integration |
| Merge versus rebase | preserve shared topology versus recreate unpublished commits |
| Squash consequence | one target commit; source commits not target ancestors |
| Revert versus reset | additive inverse for shared history versus ref movement |
| Lease force | reject if remote no longer matches expected observed ref |
| Conflict resolution | reconstruct intended behavior using both sides and base |
| Trunk prerequisites | small changes, strong automation, flags/abstraction, rapid recovery |
| Release-branch obligation | source of truth, backport direction, version/tag, retirement |
| CODEOWNERS boundary | review routing; enforcement requires repository policy |
| Merge queue | validate current target plus queued combinations |
| Emergency governance | bounded authority, minimum evidence, audit, rollback, reconciliation |
| Monorepo decision | atomicity, access, ownership, build graph, CI scale, release independence |
| Large-object response | measure history/refs; coordinate LFS/filtering before rewrite |
| Commit signing | key signed exact object; identity/key trust and revocation still required |
| Secret incident | revoke, scope exposure, preserve evidence, remediate history/control |
| Untrusted fork | isolated tokenless evaluation; privileged action after trusted review |
| Reflog boundary | local, expiring recovery record—not backup |
| Bisect quality | deterministic classification and awareness of external environment changes |
| Force-push recovery | freeze, preserve tips, locate authority, restore/integrate, notify consumers |
| Provider continuity | mirrors/backups plus metadata, policy, releases, and controlled reconciliation |
| Recovery proof | expected graph/refs, exact checks, releases/consumers, audit, customer outcome |

Review missed cards after one day, three days, and seven days.
