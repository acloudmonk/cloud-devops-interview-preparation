# Active-Recall Flashcards

[← Module overview](index.md) · [Rapid-fire revision](rapid-fire.md)

1. **Decision model?** Driver → placement → boundaries → interaction → operation → economics → evidence.
2. **Hybrid / multi-cloud?** Public plus private/edge / multiple public providers.
3. **Best default?** Place each workload well; do not split it across providers without a strong driver.
4. **Pattern set?** Tiered, environment, partitioned, analytics, edge, redundant, bursting.
5. **Connectivity checklist?** IP, BGP, DNS, capacity, latency, encryption, inspection, diversity, failover, cost.
6. **Identity model?** Federated authentication, native authorization, short-lived workload identity, independent recovery.
7. **Data record?** Authority, location, copies, consistency, sovereignty, RPO/RTO, movement, deletion, exit.
8. **Async boundary value?** Decoupling, buffer, replay, backpressure, and failure containment.
9. **Portability proof?** Target deployment and data migration under measured time, feature, cost, and operations.
10. **Platform strategy?** Common interfaces and governance with explicit provider-native implementations.
11. **Kubernetes caveat?** Common workload API does not equal end-to-end portability.
12. **Observability model?** Service-level common semantics plus local/provider evidence and independent minimum visibility.
13. **Incident model?** One command, environment leads, vendor liaison, shared timeline, authoritative data decisions.
14. **Common-mode test?** Identity, DNS, CI/CD, carrier, SaaS, telemetry, operator, and data failure.
15. **Edge autonomy?** Local safe service, identity/policy/data, queue, and deterministic reconciliation.
16. **DR proof?** Data, identity, capacity, routing, dependencies, operations, RTO/RPO, and failback exercised.
17. **Exit proof?** Export/import, replacement features, dual run, traffic, contract, deletion, skills, and elapsed time.
18. **TCO components?** Provider, link, egress, platform duplication, support, license, people, migration, testing, retirement.
19. **Governance split?** Central placement/control intent; provider and product owners implement and operate.
20. **Simplification trigger?** Driver expires, migration completes, or duplication no longer produces value.
21. **Sovereignty test?** Location plus administration, keys, support, metadata, legal access, and recovery.
22. **Conflict handling?** Authority/fencing, domain rule, idempotency, logs, reconciliation, and communication.
23. **Provider API outage posture?** Pre-provisioned capacity and data-plane operation without urgent control changes.
24. **Architect trade-off?** Outcome and independence versus latency, state, operations, cost, and skills.
25. **Answer shape?** Driver → pattern/placement → boundaries → operation/failure → economics → proof/residual risk.
