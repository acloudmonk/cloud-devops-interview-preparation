# Timed Cross-Cloud Mapping Mock Interview

[← Module 05](../05-multi-cloud-mapping/index.md)

Time: **50 minutes** · Score: **50 points** · Target: **40+**

## Candidate brief

Design a three-cloud target portfolio for a regulated company with AWS commerce,
Azure workforce/data investments, acquired GCP analytics, cross-cloud DR requests,
identity inconsistency, overlapping networks, rising egress, and limited operators.

## Interview sequence

| Time | Prompt | Points |
| --- | --- | ---: |
| 0–5 | Clarify drivers, journeys, data, SLOs, constraints | 5 |
| 5–12 | Placement options and weighted decision | 7 |
| 12–19 | Hierarchy, governance, identity, keys | 7 |
| 19–27 | Network, DNS, private connectivity, edge | 8 |
| 27–34 | Runtime, data, integration, delivery mappings | 7 |
| 34–41 | Failure, authority, recovery, quota, exercises | 7 |
| 41–46 | Operations, evidence, support, cost | 5 |
| 46–50 | Roadmap, risks, assumptions, exit triggers | 4 |

## Mandatory follow-ups

1. Federation fails in one provider.
2. Replication lags and failover creates two writers.
3. A “portable” workload fails only on GKE.
4. Egress doubles after centralized observability.

## Scorecard

Score against each row maximum. **40+** is strong. Any unsafe identity or data-authority
answer requires remediation. Record three gaps, revisit primary sources, and repeat
with changed regulatory, outage, and commercial constraints.
